## The retail game the build takes its data from: No One Lives Forever 2
## (Europe), as its setup installs it from its two discs, with Sierra's
## English 1.3 update over it, as the update's setup installs it. This list
## holds no game data. It tells build/discs.py which bytes of which image
## make each file, and what each file must be (its size and SHA-256). The
## public install scripts (build/mkinstall.py) read the files of the game
## directory from it too, from the European or the USA discs.
##
## D <id> <volume label> <volume blocks> <image size> <image SHA-256> <redump ID> <name>
##   One disc. A disc image is recognised by its volume label and its volume
##   size (blocks of 2048 bytes). The image size and SHA-256 are those of the
##   .iso of the redump dump with that ID and name. Another correct copy of
##   the disc can have another size and SHA-256: each file is checked.
##   us2alt is redump's other dump of the USA disc 2: the same cabinets at
##   the same offsets.
## U <id> <size> <SHA-256> <name>
##   The update's installer, as it was published.
## M <id> <installer> <offset> <size> <SHA-256>
##   Its payload: the one folder of the Microsoft cabinet at <offset>,
##   unpacked.
## S <set> <id> ...
##   A set of discs the public install scripts accept.
## I <set> <id> ...
##   The images that `make retail` needs.
## F <path> <size> <SHA-256>
##   One installed file ...
## W copy|is <id>:<offset>:<length> ...
##   ... and one way to read it: the byte ranges that are the file (copy),
##   or that hold its InstallShield 6 cabinet data (is). One W line for each
##   set of images it is on.
## The fields are separated by one TAB. build/discs.py describes the formats.
